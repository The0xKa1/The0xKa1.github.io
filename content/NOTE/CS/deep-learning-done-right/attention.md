# 注意力

翻译同一句话，写到人名和写到动作时，需要从源句取出的内容不同。若每次都把所有位置按同样比例混合，当前要写什么就无法改变读到的结果。在 [RNN](./rnn.md) 的编码器与解码器之间，若只传递编码器的末状态，解码器各步能查阅的源句信息就只有同一份压缩结果。怎样让同一组记录回应不同的请求？

???quote "茶铺的八个罐子"
    巷口茶铺的老板娘以前每天早上熬一大桶招牌茶，谁来都舀一杯。熬夜的学生喝了还是困，吃完火锅的人喝了还是腻，夜里咳嗽的老伯嫌它太提神，喝完更睡不着。

    后来她把大桶收了。柜台后面摆着八个罐子，茶叶原样存在里面，每个罐口贴一张小纸条，写着它管什么：解腻、提神、润嗓、安睡、消食……

    客人进门，她先问一句今天怎么了，拿这句话去对每张纸条，对得越准的罐子记分越高。分数再换成份额：高分的罐子分得多，低分的也给一小撮，八份加起来正好装满一只茶壶。然后按份额从各罐取茶叶，混在一起泡。

    学生说要熬夜赶论文，提神那罐取了大半，润嗓的放了一点。老伯说夜里咳，润嗓和安睡两罐占了多数，提神那罐只捻了几片。同样八个罐子，两壶茶喝起来完全不同。

    纸条只拿来比对，倒进壶里的是罐子里的东西。写着“消食”的那罐，装的是山楂、陈皮和一点乌龙，客人喝到的是这几样，不是那两个字。

    ![老板娘从一排茶罐里按不同分量取茶叶](/images/deep-learning-done-right/stories-v2/C01.png)

    注意力就是这样读取信息的：来源不动，每次查询拿自己的 query 去和每条的 key 打分，softmax 把分数变成总和为 1 的权重，再按权重混合各条的 value。

注意力让每次查询决定从各个位置取多少信息。它保留一组可查阅的表示，先用当前查询给各位置打分，再把分数换成权重，按权重汇聚内容。茶铺按客人的需求比对纸条、分配茶叶份额，对应的就是这套计算。[Bahdanau 等人的论文](https://arxiv.org/abs/1409.0473)把这种可学习的对齐用在循环编码器与解码器之间；同样的运算也可以作用于图像块、文本 token 或其他特征序列。

## Query、Key 与 Value {#qkv}

一次注意力查询需要区分“用什么匹配”和“取出什么内容”。当前需求的向量表示称为 query（查询）$q$；第 $j$ 条候选信息提供 key（键）$k_j$ 用来与查询打分，以及 value（值）$v_j$ 用来汇聚。故事中的需求、罐口纸条和罐内茶叶，分别对应这三个角色。若有 $S$ 个候选位置，先算分数 $e_j$，再经 softmax 得到权重 $\alpha_j$，最后得到输出 $c$：

$$
\begin{gathered}
e_j=\operatorname{score}(q,k_j),\\

\alpha_j=\frac{e^{e_j}}{\sum_{s=1}^S e^{e_s}},\\

c=\sum_{j=1}^S\alpha_jv_j.
\end{gathered}
$$

$e_j$ 可以是任意实数，softmax 将这些分数变成 $\alpha_j\ge0$ 且总和为 1 的份额。加权求和时，每个 $v_j$ 的所有通道共用权重 $\alpha_j$，所以输出 $c$ 与 $v_j$ 的维度相同。

匹配和取内容承担不同的任务：query 与 key 决定取多少，value 决定取来什么。把它们交给不同的线性投影，网络就能分别学习适合打分的表示和适合传给后续层的内容表示。

例如三个 value 为 $(2,0),(0,4),(2,2)$，权重为 $(0.5,0.25,0.25)$，输出就是 $(1.5,1.5)$。三个位置都按各自权重进入结果。梯度可通过加权和、softmax 和打分函数传回 query、key、value 的生成网络。

要看清查询如何改变读取结果，另取两条物资记录作为数值例子：固定记录的键和值，只改变查询向量。省略批量轴，令

$$
\begin{gathered}
k_1=(1,0),\quad k_2=(0,1),\\
v_1=(2,0),\quad v_2=(0,4).
\end{gathered}
$$

两个 value 的坐标依次表示粮食和淡水的数值特征。若固定各取一半，无论查询是什么，总得到 $(1,2)$。要让比例随查询改变，先用**未缩放点积** $e_j=qk_j^\top$ 打分，再用 softmax 把分数换成权重：

| 查询 | 两个分数 | softmax 权重 | 汇聚结果 |
| --- | --- | --- | --- |
| $q=(1,0)$ | $(1,0)$ | $(0.7311,0.2689)$ | $(1.4621,1.0758)$ |
| $q'=(0,1)$ | $(0,1)$ | $(0.2689,0.7311)$ | $(0.5379,2.9242)$ |

第一行的权重来自 $e/(e+1)$ 与 $1/(e+1)$；输出为 $0.7311(2,0)+0.2689(0,4)$，表中结果按未舍入的权重计算。第二行只换了查询，键和值不动，两条记录的贡献就交换了大小。

把查询逐行堆起来，就能用矩阵乘法一次完成两次读取。令 $I_2$ 为二阶单位矩阵，$Q=I_2$、$K=I_2$、$V=\left[\begin{smallmatrix}2&0\\0&4\end{smallmatrix}\right]$ 都是 $(2,2)$ 矩阵。$QK^\top$ 的每一行对应一个查询，每一列对应一条记录；沿行做 softmax 得到 $(2,2)$ 的权重矩阵，再乘 $V$，两行输出就是表中的结果。[D2L §11.1](https://d2l.ai/chapter_attention-mechanisms-and-transformers/queries-keys-values.html)也将这一运算写成由查询决定系数的值向量加权和。

## 加性注意力与缩放点积注意力 {#scores}

点积要求查询和键有相同的宽度，前面的例子中两者都只有两个坐标。实际翻译时，解码状态与源端表示的宽度可能不同，需要先把它们映射到可以比较的空间。

加性注意力先把 query 和 key 映射到同一内部宽度，再用小网络输出标量。采用行向量：

$$
e_{t,j}=\tanh(q_tW_q+k_jW_k+b)w_a.
$$

$t$ 表示查询位置，$j$ 表示源位置。输入宽度分别为 $d_q$ 和 $d_k$，即 $q_t\in\mathbb R^{d_q}$、$k_j\in\mathbb R^{d_k}$。选定内部宽度 $d_a$ 后，$W_q\in\mathbb R^{d_q\times d_a}$、$W_k\in\mathbb R^{d_k\times d_a}$、$b\in\mathbb R^{d_a}$、$w_a\in\mathbb R^{d_a\times1}$。两个投影相加后得到 $d_a$ 维向量，经 $\tanh$ 再乘 $w_a$，便得到一个标量分数。

在翻译中，Bahdanau 的解码器用前一步解码状态查询源端的双向编码状态；各源位置共享这套打分参数。

缩放点积注意力则让 query 与 key 有相同宽度 $d_k$，用内积直接打分。设 $B$ 为批量中的样本数，$L$ 为每条样本的查询数，$S$ 为候选数，$d_v$ 为 value 的宽度。把查询和候选堆成张量，便得到：

$$
\begin{aligned}
Q&\in\mathbb R^{B\times L\times d_k},\\
K&\in\mathbb R^{B\times S\times d_k},\\
V&\in\mathbb R^{B\times S\times d_v},\\
E&=\frac{QK^\top}{\sqrt{d_k}}+M,\\
A&=\operatorname{softmax}_{\text{源位置}}(E),\\ C&=AV.
\end{aligned}
$$

$K^\top$ 只交换最后两轴，得到 $(B,d_k,S)$；$E,A$ 为 $(B,L,S)$；输出 $C$ 为 $(B,L,d_v)$。$M$ 是加到分数上的 mask（掩码），用来指定哪些候选位置可见，其形状可以广播到分数张量。每个查询沿 $S$ 个源位置做 softmax，因此 $A$ 的每一行给出该查询的读取比例。

为什么除以 $\sqrt{d_k}$？若各分量独立、均值为零、方差为 1，点积是 $d_k$ 项之和，方差为 $d_k$。宽度增加时，大分数容易使 softmax 接近只选一个位置，梯度也随之变小。除以 $\sqrt{d_k}$ 后，在这一假设下分数方差回到 1。这是[Transformer 原论文 §3.2.1](https://arxiv.org/abs/1706.03762)采用缩放的理由。

回到前面固定的两条候选信息，查询和键的宽度 $d_k=2$。在点积上加入标准缩放后，第一个查询的分数变成 $(1/\sqrt2,0)$，权重约为 $(0.6698,0.3302)$，输出约为 $(1.3395,1.3210)$；第二个查询得到 $(0.3302,0.6698)$ 和 $(0.6605,2.6790)$。这就是同一组 $Q,K,V$ 上的 $\operatorname{softmax}(QK^\top/\sqrt2)V$，所有位置均可见，所以 $M=0$。

## 注意力计算示例 {#attention-example}

将候选位置从两个增加到三个，可以继续检查打分、归一化和汇聚如何衔接。令 $B=L=1,S=3,d_k=d_v=2$，即一条样本中的一个查询读取三个候选，查询、键和值的宽度都是 2。省略批量轴：

$$
\begin{gathered}
Q=\begin{bmatrix}1&0\end{bmatrix},\\

K=\begin{bmatrix}1&0\\0&1\\1&1\end{bmatrix},\\

V=\begin{bmatrix}2&0\\0&4\\2&2\end{bmatrix}.
\end{gathered}
$$

不加 mask，先得到 $QK^\top=[1,0,1]$，缩放后为 $[0.7071,0,0.7071]$。指数约为 $[2.0281,1,2.0281]$，除以总和后

$$
\begin{gathered}
A\approx[0.4011,0.1978,0.4011],\\

C\approx[1.6044,1.5933].
\end{gathered}
$$

第一个和第三个 key 在查询 $Q$ 下得分相同，因此它们的 value 获得相同权重。第三个候选的加入也扩大了 softmax 的分母，使前两个位置的权重随之改变。

若第三个位置只是为凑齐序列长度而补上的 padding，就应将它排除在读取范围外。在分数上加上 $M=[0,0,-\infty]$，softmax 变为 $[0.6698,0.3302,0]$，输出变为 $[1.3395,1.3210]$。屏蔽使第三项的指数变为 0，其余两项重新分配总和为 1 的权重，结果便回到了两个候选的算例。

可以用下面的 NumPy 运算复算；减去行最大值能避免指数溢出，而不改变 softmax。

```python
import numpy as np

q = np.array([[1., 0.]])
k = np.array([[1., 0.], [0., 1.], [1., 1.]])
v = np.array([[2., 0.], [0., 4.], [2., 2.]])
scores = q @ k.T / np.sqrt(k.shape[-1])
weights = np.exp(scores - scores.max(axis=-1, keepdims=True))
weights /= weights.sum(axis=-1, keepdims=True)
print(weights)
print(weights @ v)
```

## 自注意力、交叉注意力与 mask {#mask}

同一句中的词需要互相取信息，翻译的目标词则需要查询另一句。两种任务沿用同一个汇聚式，区别在于查询、键和值从哪里来。对续写任务，还必须把尚未生成的位置从可见集合中删去。

自注意力的三组投影来自同一个序列 $X\in\mathbb R^{B\times T\times d}$：$Q=XW_Q,K=XW_K,V=XW_V$。其中 $T$ 是序列长度，$d$ 是输入宽度。$W_Q,W_K,W_V$ 三个投影矩阵分别学习如何提出查询、如何参与匹配和提供什么内容，所以 $Q,K,V$ 的来源相同，数值通常不同。输出第 $t$ 行是该位置查询整条允许访问的序列后得到的表示。

交叉注意力的查询来自目标序列 $Y\in\mathbb R^{B\times L\times d_y}$，键和值来自源序列 $X\in\mathbb R^{B\times S\times d_x}$。键和值共享源序列，查询则决定要为哪些目标位置取信息。

例如一个批量包含两组翻译样本，即 $B=2$，每组目标长 3、源长 5。将查询和键投影到宽度 4，将值投影到宽度 6，得到 $Q:(2,3,4),K:(2,5,4),V:(2,5,6)$，分数为 $(2,3,5)$，输出为 $(2,3,6)$。输出长度跟查询走；键和值的长度必须一致，才能逐位置配对。

续写时，位置 $t$ 的输入用于预测第 $t+1$ 个 token，可用的信息只有截至 $t$ 的前缀。训练中即使整条序列已经给出，也要用因果 mask 保持这一读取范围：允许查看 $j\le t$ 的位置，将后续位置的分数设为 $-\infty$，使其 softmax 权重为 0。

$$
M_{t,j}=\begin{cases}0,&j\le t,\\-\infty,&j>t.\end{cases}
$$

对长度 3 的序列，mask 为

$$
M=\begin{bmatrix}0&-\infty&-\infty\\0&0&-\infty\\0&0&0\end{bmatrix}.
$$

Padding mask 按每条样本的真实长度屏蔽补齐的键位置，因果 mask 则按查询位置屏蔽未来内容。两种限制可以同时施加：将两个加性 mask 相加，只有都允许访问的位置才会留下。

为配合下一节的多头计算，分数张量会多出一个“头”轴，轴顺序为批量、头、查询位置、源位置。Padding mask 常整理为 $(B,1,1,S)$，以便广播到所有头、所有查询；因果 mask 常为 $(1,1,T,T)$，在整个批量和各头之间共用。

每个有效查询至少要留下一个可见键；整行都为 $-\infty$ 时，通常的 softmax 会产生未定义值。Padding 查询对应的输出也应从损失和后续有效位置汇聚中排除。布尔 mask 里“真”代表什么，各接口约定不一；[PyTorch MultiheadAttention 文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.MultiheadAttention.html)规定被屏蔽的位置为 `True`。

## 多头注意力 {#multihead}

一个位置可能同时需要主语信息与邻近修饰语。只用一个权重矩阵时，每个查询给所有 value 通道共用一套位置比例，怎样才能保留几种不同的读法供后续层组合？

多头注意力用多组独立的权重保留不同的读取结果。它先将输入投影成多组较窄的 query、key、value，每组称为一个头，各自打分并汇聚内容，再将结果拼接，交给输出投影混合。以自注意力为例：

$$
\begin{gathered}
Q_i=XW_Q^{(i)},\\ K_i=XW_K^{(i)},\\ V_i=XW_V^{(i)},\\
\mathrm{head}_i=\operatorname{Attention}(Q_i,K_i,V_i),
\\

Z=\operatorname{Concat}(\mathrm{head}_1,\ldots,\mathrm{head}_h),\\
\operatorname{MHA}(X)=ZW_O.
\end{gathered}
$$

$h$ 为头数。常用 $d_k=d_v=d/h$，此时每个投影矩阵为 $(d,d/h)$，拼接恢复宽度 $d$，输出矩阵 $W_O$ 为 $(d,d)$。各头学到什么关系，由训练目标决定。

取 $B=2,T=3,d=8,h=2$，每头宽度就是 4。实现时可先用一次线性层完成所有头的 QKV 投影，再把通道拆成头轴和每头的特征轴。各步形状如下：

| 运算 | 张量尺寸 |
| --- | --- |
| 输入 $X$ | $(2,3,8)$ |
| 一次线性层同时投影 QKV | $(2,3,24)$ |
| 切成 Q、K、V 并拆头、转轴 | 各 $(2,2,3,4)$ |
| 每头 $QK^\top/\sqrt4$ | $(2,2,3,3)$ |
| 沿最后一轴 softmax，再乘 V | $(2,2,3,4)$ |
| 转回位置在前，再拼接头 | $(2,3,8)$ |
| 乘 $W_O:(8,8)$ | $(2,3,8)$ |

QKV 的合并投影权重为 $(8,24)$，输出投影为 $(8,8)$，共 $192+64=256$ 个权重；带偏置再加 $24+8=32$，总计 288。固定总宽度 $d$ 时，增加头数同时减小每头宽度，这个标准配置的投影参数总量仍是 $4d^2+4d$。

拆头时还要让每个头沿序列位置计算注意力。拆分特征轴后，张量的轴顺序是批量、位置、头、每头特征，需要再交换头轴与序列轴，才能得到表中的 $(2,2,3,4)$。reshape 负责拆轴，转轴负责把位置放到正确的维度。

## 训练与计算复杂度 {#training-cost}

注意力的读取方式由下游任务的损失来训练。把输出送到分类器、解码器或其他网络，损失的梯度就能沿加权和与打分运算传回，更新 $W_Q,W_K,W_V,W_O$。

softmax 让一行中的各个分数共同决定权重。它的导数为 $\partial\alpha_j/\partial e_k=\alpha_j(\delta_{jk}-\alpha_k)$，其中 $\delta_{jk}$ 在 $j=k$ 时为 1，否则为 0。改变某个分数，同一行的其他权重也会跟着变。

若无位置表示和位置相关 mask，任意重排输入会让自注意力输出按同样顺序重排；模块无法单凭内容判断两个相同 token 的先后。[Transformer](./transformer.md)通过引入位置信息来区分顺序，并将注意力与逐位置前馈网络、残差和归一化组合成完整的网络层。

对长度 $T$、宽度 $d$ 的标准自注意力，QK 与 AV 两次乘法总量级为 $O(BT^2d)$，投影为 $O(BTd^2)$。前者随序列长度的平方增长，因为每个查询都要与所有候选位置配对。

计算量之外，还要考虑保存中间结果的显存。显式保存各头的分数需要 $B h T^2$ 个元素。取 $B=1,h=8,T=4096$，单个分数张量有 134,217,728 个元素，float32 就是 512 MiB，尚未计入梯度和其他激活。融合实现可以避免完整保存这个张量，但全连接位置交互本身仍有二次计算量。[FlashAttention 原论文](https://arxiv.org/abs/2205.14135)解释了分块计算如何减少高带宽显存读写。

与 [RNN](./rnn.md) 比较，全序列自注意力在一层内就能让两个可见位置直接交换信息；RNN 需要沿状态链传播。因果 Transformer 训练可以并行处理所有已知位置，实际生成时仍要等上一个新 token 产生后再预测下一个。

分块计算与在线 softmax 的递推和算例见[分块注意力](./efficient-sequence-models.md#flash-attention)。
