# 预训练与微调

[训练循环](./data-and-training.md#training-loop)从随机参数开始，每个特征都要由当前数据学出来。如果新任务只有几百张图片，已有模型从其他图片中学到的结构能否继续使用？我们可以从已有模型的参数出发训练，再用同一份验证集比较：只改输出部分是否足够，还是需要让内部特征也跟着调整。

???quote "医院后门"
    市一院的物资组要招一个司机，在院区之间送药品和标本。来应聘的乔师傅开了十二年出租车，城里哪条路几点堵、哪个路口好掉头，他心里都有数。

    组长先想起去年的事。去年招的人开过货车，组里让他跟新人一起上三周培训，从认路、看导航讲起。他本来会的东西被重讲一遍，反倒跟原来的习惯打架，三周下来送错了好几趟。

    这次组长没让乔师傅学开车，也没让他学认路。乔师傅不熟的是到了以后的事：标本要送检验科的后门，冷链药品走地下一层的货梯，急诊的东西不能在正门停。组长给了他一本薄薄的交接手册，第一周只照着手册改最后那几十米。手册写了又改，他开车的路子一点没动。

## 预训练 {#pretraining}

预训练让新任务从已经学到的特征出发。故事里，乔师傅先积累了认路和开车的经验，再学习医院的交接要求；模型也可以先在源数据上训练，再用目标任务的数据调整参数。

从头训练通常随机初始化参数 $\theta_0$，再在目标数据 $D_{\text{target}}$ 上优化。预训练则先在源数据上求得参数 $\theta_{\text{pre}}$，随后用它初始化目标模型。模型中负责把内部特征转换为预测结果的部分称为输出头。两阶段可以保留相同的主体结构、换用不同输出头，也可以继续使用原输出头。

两阶段通过各自的损失函数决定要学什么。$\theta_{\mathrm{pre}}$ 由源数据上的损失得到，目标阶段从它出发最小化目标任务损失 $L_{\mathrm{target}}$。设计每一阶段时，都要让输出、标签与损失彼此匹配。[学习信号](./problem-and-learning.md)区分目标从哪里来，[损失章](./losses.md#matching)规定这些目标怎样进入计算。

预训练的预测目标可以来自标签，也可以由样本本身构造。监督预训练使用人工或已有系统提供的标签，例如让视觉编码器学习大规模图像分类。自监督预训练则从样本中取出一部分作为预测目标，例如遮住文本的一部分并预测它，或用前缀预测下一 token。

BERT 使用遮蔽语言建模等目标预训练双向 Transformer，再针对下游任务微调。遮蔽位置可以利用左右上下文；自回归模型在预测下一 token 时只能读取前缀。[BERT 原论文 §3](https://aclanthology.org/N19-1423/)给出了预训练与微调的连接方式。

自回归训练通过错开输入与目标，让每个位置学习预测下一项。某条完整序列是 `[BOS, 我, 爱, 学习, EOS]`，其中 BOS 和 EOS 分别标记序列的开始与结束。输入可取前四项，目标取后四项：读到 BOS 时预测“我”，读到“我”时预测“爱”，依此类推。

若批次大小为 2、有效长度为 4、词表大小为 10,000，输入 ID 的形状为 $[2,4]$，网络输出 logits 为 $[2,4,10000]$，目标为 $[2,4]$。每个位置的 10,000 个 logits 对应词表中各个 token 的分数，转成概率后用于计算真实下一项的负对数概率。用 $i$ 表示样本编号、$t$ 表示序列位置，$x_{i,\le t}$ 表示截至位置 $t$ 的前缀，损失为

$$
\begin{gathered}
L_{\mathrm{LM}}=-\frac1M\sum_{i,t}m_{it}\log p_\theta(x_{i,t+1}\mid x_{i,\le t}),
\\
 M=\sum_{i,t}m_{it}.
\end{gathered}
$$

$m_{it}$ 在有效目标位置取 1，在忽略的位置取 0，因此 $M$ 是计入损失的 token 数。式中的 $p_\theta$ 是模型根据前缀给出的下一 token 概率。某些模型接口会在内部移动 labels；使用这样的接口时传完整标签，由接口完成输入与目标的错位。

这与[逐位置交叉熵](./losses.md#reduction)使用同一分母：损失只在有效预测位置求和，再除以有效 token 数。迁移到新的语料时，改变的是样本、起始参数及允许更新的部分；输出仍是给定前缀下的下一项概率。

复用预训练权重时，需要一并保留与它配套的输入处理和模型配置，包括分词器、词表、特殊 token、输入归一化和结构配置。换掉其中任何一项，权重接收到的输入含义都可能变。

旧模型的输出类别可能和新任务完全不同。先保留产生表示的部分、重建最后的任务头，可以单独检验已有表示是否足够；表现不足时再扩大可更新范围。

## 冻结与微调 {#update-scope}

选择更新范围，可以先把网络拆成提取特征和完成预测两部分。把网络写成 $h=f_\theta(x)$、$z=g_\phi(h)$：编码器 $f_\theta$ 把输入 $x$ 转成表示 $h$，任务头 $g_\phi$ 再把表示转成预测分数 $z$，两部分的参数分别记为 $\theta$ 和 $\phi$。只训练任务头，就像故事中先保留司机的驾驶习惯、只调整到院后的交接方式。

以一个图像分类批次为例，$B$ 表示批次大小。输入 $X\in\mathbb R^{B\times3\times224\times224}$，视觉编码器输出 $H\in\mathbb R^{B\times768}$，也就是每张图片得到一个 768 维向量。新任务有 5 类，线性头参数为 $W\in\mathbb R^{5\times768}$、$b\in\mathbb R^5$，输出 logits 为 $[B,5]$。任务头共 $768\times5+5=3845$ 个参数；冻结编码器时，只更新这些参数。

如果固定的表示还不能满足新任务，就可以逐步扩大更新范围：

| 方式 | 本次更新的参数 | 用途与训练代价 |
| --- | --- | --- |
| 冻结编码器，只训练线性头 | $\phi$ | 直接检查预训练表示能否线性区分类别，可缓存固定特征 |
| 解冻末端若干层 | 部分 $\theta$ 与 $\phi$ | 让较高层表示适应新任务 |
| 全参数微调 | 全部 $\theta,\phi$ | 所有表示可调整，需要保存全部可训练参数的梯度和优化器状态 |
| LoRA 等参数高效微调 | 指定的新参数，通常另含任务头 | 限制更新的表示方式，减少可训练状态 |

冻结编码器，是将其参数设为 `requires_grad=False`，让训练跳过这些参数的梯度计算。要让提取出的特征保持固定，还需将编码器设为 `eval()`，使 BatchNorm 的统计量保持不变并关闭 Dropout。参数是否求梯度、模块是否采用评估模式，需要分别设置。

是否使用 `no_grad()`，取决于梯度是否需要穿过编码器。当冻结编码器只位于最前端，且不需要对其输入求导时，可以在 `no_grad()` 中提取特征；若冻结层夹在可训练层之间，仍需保留对输入的梯度路径，才能更新更早的可训练层。

下面的片段假设已经加载与任务匹配的 `encoder`，且它输出 $[B,768]$。它展示“固定特征、训练新头”的实际操作，数据加载复用[训练章](./data-and-training.md#training-loop)：

```python
for p in encoder.parameters():
    p.requires_grad_(False)
encoder.eval()
head = torch.nn.Linear(768, 5)
optimizer = torch.optim.AdamW(head.parameters(), lr=1e-3)

head.train()
for images, labels in train_loader:
    with torch.no_grad():
        features = encoder(images)
    logits = head(features)
    loss = torch.nn.functional.cross_entropy(logits, labels)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()
```

全参微调要让编码器也参与更新：恢复编码器梯度，移除特征提取时的 `no_grad()`，并把编码器参数加入优化器。编码器已有预训练参数，任务头则刚随机初始化，因此可以给编码器较小学习率、任务头较大学习率，再用验证集选择具体取值。

分阶段解冻时，也要同步调整优化器，使新增的可训练参数进入更新范围。如果重新创建优化器，原有的矩估计会被重置，也就是 AdamW 累积的梯度一阶、二阶统计量需要重新开始。[PyTorch 迁移学习教程](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html)展示了冻结与全参更新两种流程。

如果新任务需要改变内部线性映射，只训练最后一层可能不够，而更新所有大矩阵又要保存大量训练状态。能否保留原矩阵，另外学习一个受约束的增量？

## 低秩适配（LoRA） {#lora}

![LoRA 原论文结构图，输入同时进入冻结的预训练权重和可训练的低秩 A、B 分支，两条输出相加](/images/deep-learning-done-right/training/lora-structure.png)

图 1：Hu 等，2021，[LoRA](https://arxiv.org/abs/2106.09685v2) Figure 1，裁去周围正文。蓝色为冻结权重，橙色为可训练分支。

LoRA 在原线性层旁增加一条可训练分支，用两个较小矩阵表达权重增量。考虑线性层 $y=W_0x$，其中 $d_{\text{in}}$ 和 $d_{\text{out}}$ 分别是输入、输出宽度，$x\in\mathbb R^{d_{\text{in}}}$，$W_0\in\mathbb R^{d_{\text{out}}\times d_{\text{in}}}$。LoRA 冻结 $W_0$，让新增矩阵 $A$、$B$ 学习对输出的修正：

$$
\begin{gathered}
y=W_0x+\frac{\alpha}{r}BAx,
\\
 A\in\mathbb R^{r\times d_{\text{in}}},\\

B\in\mathbb R^{d_{\text{out}}\times r}.
\end{gathered}
$$

$r$ 是选定的秩上限，通常远小于输入输出宽度；$\alpha$ 控制更新缩放。$Ax$ 先得到 $r$ 维向量，$B$ 再把它映射回输出宽度。$BA$ 的秩至多为 $r$，因此用较少参数表达一个受约束的权重更新。

若 $d_{\text{in}}=d_{\text{out}}=4096,r=8$，原矩阵有 $16,777,216$ 个参数，LoRA 分支有 $8(4096+4096)=65,536$ 个，是该原矩阵参数量的 $0.390625\%$。训练时存储原矩阵和新增分支，但只为新增分支保存参数梯度及优化器状态，所以这里的比例描述的是可训练权重的减少。

用一个二维例子可以看清新增分支怎样改变输出。设 $W_0=I_2$，$x=(2,1)^\top$，$A=[1,-1]$，$B=(0.1,0.2)^\top$，取 $r=\alpha=1$。有 $Ax=1$，$BAx=(0.1,0.2)^\top$，输出为 $(2.1,1.2)^\top$。更新矩阵为

$$
BA=\begin{bmatrix}0.1&-0.1\\0.2&-0.2\end{bmatrix},
$$

这个更新矩阵的两行成比例，秩为 1，与选定的 $r=1$ 一致。

推理时可以把增量合回原权重。对普通线性权重且关闭 LoRA Dropout 时，合并成 $W_{\mathrm{merged}}=W_0+(\alpha/r)BA$ 后计算 $W_{\mathrm{merged}}x$，输出相同；量化或重新量化则会另带误差。

原论文采用随机初始化 $A$、零初始化 $B$，使初始增量为零。此时第一步 $A$ 的梯度因 $B=0$ 为零，$B$ 通常可得到非零梯度；更新 $B$ 后，两者都能学习。[原论文 §4.1](https://arxiv.org/pdf/2106.09685v2)给出了参数化与初始化方法。

下面的最小线性实现把原层保存在 `base` 中，另外创建可训练的 $A$、$B$，前向时将两条分支相加。代码采用上述初始化方式，不使用 Dropout，并保留、冻结传入层的已有偏置：

```python
import math
import torch
from torch import nn

class LoRALinear(nn.Module):
    def __init__(self, base, rank=8, alpha=8):
        super().__init__()
        self.base = base
        self.base.requires_grad_(False)
        self.scale = alpha / rank
        self.A = nn.Parameter(base.weight.new_empty(rank, base.in_features))
        self.B = nn.Parameter(base.weight.new_zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))

    def forward(self, x):
        return self.base(x) + self.scale * (x @ self.A.T @ self.B.T)

layer = LoRALinear(nn.Linear(4, 3), rank=2, alpha=2)
x = torch.randn(5, 4)
assert layer(x).shape == (5, 3)
trainable = sum(p.numel() for p in layer.parameters() if p.requires_grad)
assert trainable == 2 * (4 + 3)
```

对 Transformer 进行 LoRA 微调时，先确定在哪些线性层加入分支，例如注意力的 query、value 投影，再为各层设置 rank、缩放和 Dropout。这些设置决定了模型可以在哪些位置、以多大的秩调整原有映射。

冻结 $W_0$ 后，反向传播仍需通过该层把梯度传到更早的可训练分支。因此基础模型的前向计算要保留这条梯度路径，不能整体放进 `no_grad()`；省去的是 $W_0$ 的参数梯度及其优化器状态。

让语言模型按要求作答时，输入既包含用户请求，也包含期望回答。哪些位置是上下文，哪些位置要计入训练目标？标签掩码决定哪些位置参与损失计算；前面讨论的冻结范围和 LoRA 则决定这些损失可以更新哪些参数。

## 指令微调 {#instruction-tuning}

监督指令微调通过提示和参考回答，训练模型根据用户请求生成回答。训练时把两者组织为一个序列。比如 `[用户问题, 分隔符, 助手回答, EOS]`，模型读取完整前缀，用下一 token 目标学习回答。有的设置只对助手回答及 EOS 计算损失，提示位置和 padding 的标签设为忽略值。提示仍作为上下文参与前向计算，训练损失则集中在助手需要生成的内容上。

把提示位置的标签设为忽略值，只改变损失的计算范围。模型在当前位置能读取哪些信息，由因果注意力掩码控制；哪些位置的预测计入损失，由标签掩码控制。处理多轮对话时，还要确定是否监督所有助手轮次，并检查截断后的序列是否保留了所需的问题和回答。

损失汇总方式决定不同长度的回答对训练有多大影响。按 token 平均，就是把所有有效位置的损失相加，再除以有效 token 总数，因此有效目标较多的长样本权重更高。按序列平均，则先求每条序列内有效位置的平均损失，再对序列取平均，使每条样本的总权重接近。使用梯度累积时，也要按选定方式统计有效 token 或序列，保持损失分母一致。

评价生成结果时，还需固定解码温度、最大长度和停止条件，才能在相同生成设置下比较微调方案，详见[评价章](./evaluation-and-generalization.md#generative-evaluation)。

比较微调效果时，需要把参数更新方式与训练预算一并记录。保留不更新或只更新任务头的基线，并让各方案共享数据划分与评价口径，才能判断扩大更新范围带来了多少收益。

## 微调实验 {#procedure}

一次微调实验可以按数据检查、小规模训练、验证集选型、最终测试的顺序推进。先确认输入和训练流程正确，再投入更多训练预算比较更新范围。

1. 固定目标任务、数据划分和指标，排查训练文本与测试题的重复。保留基础模型直接评估或只训练头的结果作为基线。
2. 核对模型配置、输入预处理、标签映射和最大长度。检查送入模型的实际 batch，确认预处理后的张量与标签对应。
3. 选择更新范围并打印可训练参数名、数量。先在几十条样本上确认损失可以下降，再扩大训练。
4. 使用相同验证集比较学习率、更新步数、冻结范围或 LoRA rank。保存验证最优检查点和完整设置。
5. 在目标任务上评价，并用原任务或通用能力子集检查遗忘，也就是微调后原有任务表现的退步。目标任务分数提高而旧任务退步时，记录这项取舍，可再比较较小学习率、较少更新或混合数据。
6. 方案确定后做最终测试。LoRA 交付包含适配器权重、对应基础模型版本和配置；更换基础模型会改变适配器叠加的对象。

更新范围要结合数据和任务来选。源数据与目标数据的领域是否接近、学习目标是否一致、目标样本有多少，都会影响冻结或微调的效果。因此，比较从头训练、冻结、全参和 LoRA 时，要把数据量、可训练参数量、训练预算与推理成本一起列出，让分数差异对应到具体的训练设置。

预训练的参数与数据预算见[计算预算](./scaling-and-experts.md#compute-budget)；指令微调之后，成对回答偏好的使用方式见[偏好数据](./alignment-and-reasoning.md#preference-data)。
